\part{Current Activities}

\begin{frame}{Current Activities}
   The main activity is currently the \alert{inclusion} of the \alert{\texttt{MQTTBroker/MQTTIntegrator}} reference applications in \alert{\texttt{OpenWRT}}, an \alert{Open-Source Firmware} based on \alert{Linux} (Wi-Fi) router.

   \color{fh-ooe-red}{Almost all proprietary router firmware for home routers is based on \texttt{OpenWRT}.}
   \begin{itemize}
     \item Two libraries were not yet part of \texttt{OpenWRT}
     \begin{itemize}
       \item \alert{\texttt{Easylogging++}} (Logging Library)
       \item \alert{\texttt{libucontext}} (cooperative multithreading)
       \begin{itemize}
         \item ARM: Bug fix
         \item Aarch64: Bug Fix
       \end{itemize}
       OpenWRT uses the \alert{\texttt{musl}} instead of the \alert{\texttt{GNU-C}} library. In contrast to the \texttt{GNU-C} library, \texttt{muls} does not provide the system calls for cooperative multithreading, as these have been removed from the standard since \texttt{POSIX.1-2008}.
     \end{itemize}
     \item Update to \alert{\texttt{upstream}} for two packages of \texttt{OpenWRT}
     \begin{itemize}
       \item \alert{\texttt{File}}
       \item \alert{\texttt{nlohmann\_json}}
     \end{itemize}
     \item Fix \alert{\texttt{segfault}} in the \alert{asynchronous API} of \alert{\texttt{libmariadb}} by adding linking against \alert{\texttt{libucontext}}
     \item And ultimately, \alert{\texttt{SNode.C}} itself has to be included in OpenWRT, since the MQTT applications are based on SNode.C.
   \end{itemize}
\end{frame}
